Text Embeddings and Vector Search

What is a text embedding?
A text embedding is a fixed-length list of floating-point numbers (a vector) that represents the meaning of a piece of text. Two texts that mean similar things will have embedding vectors that point in nearly the same direction in high-dimensional space, regardless of whether they share the same words. This makes embeddings ideal for semantic search — finding documents that are relevant to a query even when they use different vocabulary.

For example:
- "How do I reset my password?" and "Steps to change my login credentials" will have similar embeddings, even though they share no keywords.
- "The weather is sunny today" will have a very different embedding from both, because it discusses a completely different topic.

How are embeddings generated?
A dedicated embedding model (such as qwen3-embedding-0.6b or OpenAI's text-embedding-3-small) is used to convert text into a vector. The model is a neural network trained on large amounts of text specifically to produce geometrically meaningful vectors. You do not need to understand the neural network internals to use embeddings — you just pass text in and get a vector out.

What is cosine similarity?
Cosine similarity measures the angle between two vectors. A value of 1.0 means the vectors point in exactly the same direction (highly similar), 0.0 means they are perpendicular (unrelated), and -1.0 means they point in opposite directions (opposite meaning, rare in practice).

Formula:
    cosine_similarity(A, B) = dot(A, B) / (norm(A) * norm(B))

In Python using numpy:
    import numpy as np
    def cosine_similarity(a, b):
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

Vector search in a RAG pipeline:
1. During ingestion, every document chunk is embedded and its vector is stored in a database alongside the original text.
2. At query time, the user's question is also embedded using the same model.
3. The cosine similarity between the query vector and every stored document vector is computed.
4. The top-K chunks with the highest similarity scores are retrieved and passed to the LLM.

Why not keyword search?
Keyword search (like SQL LIKE or full-text search) only finds documents that contain the exact words in the query. Vector search finds documents that are semantically related, even when phrased differently. For Q&A systems this is a significant advantage.

Storing embeddings in SQLite:
SQLite does not natively support vector operations, but embeddings can be stored as JSON-serialised arrays (TEXT column). At query time, all embeddings are loaded into memory as numpy arrays and cosine similarity is computed in Python. This brute-force approach is acceptable for small knowledge bases (up to a few thousand chunks). For larger collections, specialised vector databases such as FAISS, Chroma, or Qdrant can be used.

Dimensionality:
The qwen3-embedding-0.6b model produces 1536-dimensional vectors. Each float32 value takes 4 bytes, so one embedding = 6 KB. A knowledge base of 1000 chunks ≈ 6 MB in memory — trivially small for a modern laptop.
